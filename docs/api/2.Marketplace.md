# nodeline.id — Marketplace Module Spec & Checklist

> Modul kedua, dibangun setelah Auth. Menggunakan `JwtAuthGuard` & `RolesGuard` dari modul Auth untuk proteksi endpoint beli & admin.

---

## 1. Ringkasan Alur Bisnis

- Produk bisa dilihat publik (tanpa login), **beli wajib login**.
- Satu produk punya **StockUnit** — satu paket konten pengiriman (bisa 1 API key, banyak key sekaligus, atau link/teks bebas), jumlah key per paket diatur di level produk (`keysPerUnit`).
- Assignment StockUnit ke buyer bisa **otomatis (FIFO)** atau **manual dipilih admin** — dua-duanya didukung mekanisme yang sama.
- Payment **manual dulu** (gateway belum di-approve) — dirancang pakai abstraksi `PaymentProvider` supaya gampang ganti nanti tanpa redesign.
- **Garansi** fleksibel per produk (masa berlaku & jumlah klaim beda-beda tiap produk), approve/reject manual oleh admin.
- **Refund** manual — buyer input nomor WhatsApp saat checkout, verifikasi & proses refund dilakukan admin sendiri di luar sistem otomatis.
- Stok ditampilkan ke buyer sebagai **status** (Tersedia/Habis), bukan angka pasti.
- Review hanya boleh dari buyer dengan order **FULFILLED** (verified purchase).
- **Kategori** — produk bisa di-group dalam kategori untuk navigasi lebih baik.

## 6. Logic Kritis: Assignment dengan Transaction Lock

Ini bagian paling penting — cegah dua order dapat `StockUnit` yang sama.

```typescript
// stock.service.ts
async assignAvailableUnit(orderItemId: string, tx: DrizzleTransaction) {
  const orderItem = await tx.query.orderItems.findFirst({ where: eq(orderItems.id, orderItemId) });

  // Row lock: kunci satu StockUnit AVAILABLE untuk produk ini, cegah row lain ambil bareng
  const [unit] = await tx.execute(sql`
    SELECT * FROM stock_units
    WHERE product_id = ${orderItem.productId} AND status = 'AVAILABLE'
    ORDER BY created_at ASC
    LIMIT 1
    FOR UPDATE SKIP LOCKED
  `);

  if (!unit) {
    return null; // pool kosong → biarkan order tetap PENDING_FULFILLMENT
  }

  await tx.update(stockUnits)
    .set({ status: 'SOLD', soldAt: new Date() })
    .where(eq(stockUnits.id, unit.id));

  await tx.insert(fulfillments).values({
    orderItemId,
    stockUnitId: unit.id,
    assignedBy: null, // auto-assign
  });

  return unit;
}
```

> `FOR UPDATE SKIP LOCKED` penting: kalau ada request lain yang lagi proses row yang sama, request ini skip ke row berikutnya alih-alih nunggu/deadlock — cocok untuk kasus rebutan stok seperti ini.

**Assignment hanya boleh dipanggil setelah payment dikonfirmasi**, bukan pas order dibuat:

```typescript
// payments.service.ts
async confirmPayment(orderId: string, adminId: string) {
  return this.db.transaction(async (tx) => {
    await tx.update(orders)
      .set({ status: 'PAID_PENDING_FULFILLMENT' })
      .where(eq(orders.id, orderId));

    const items = await tx.query.orderItems.findMany({ where: eq(orderItems.orderId, orderId) });

    for (const item of items) {
      const unit = await this.stockService.assignAvailableUnit(item.id, tx);
      if (unit) {
        await tx.update(orders).set({ status: 'FULFILLED' }).where(eq(orders.id, orderId));
      }
      // kalau unit null, order tetap PAID_PENDING_FULFILLMENT, nunggu restock
    }

    await this.auditLog.record(tx, { action: 'CONFIRM_PAYMENT', orderId, actorId: adminId });
  });
}
```

## 7. Logic Kritis: Enkripsi Konten StockUnit

```typescript
// crypto.util.ts
import { createCipheriv, createDecipheriv, randomBytes } from 'crypto';

const ALGORITHM = 'aes-256-gcm';
const KEY = Buffer.from(process.env.STOCK_ENCRYPTION_KEY, 'hex'); // 32 byte, dari secret manager

export function encryptContent(plain: string): string {
  const iv = randomBytes(12);
  const cipher = createCipheriv(ALGORITHM, KEY, iv);
  const encrypted = Buffer.concat([cipher.update(plain, 'utf8'), cipher.final()]);
  const authTag = cipher.getAuthTag();
  return Buffer.concat([iv, authTag, encrypted]).toString('base64');
}

export function decryptContent(encoded: string): string {
  const data = Buffer.from(encoded, 'base64');
  const iv = data.subarray(0, 12);
  const authTag = data.subarray(12, 28);
  const encrypted = data.subarray(28);
  const decipher = createDecipheriv(ALGORITHM, KEY, iv);
  decipher.setAuthTag(authTag);
  return Buffer.concat([decipher.update(encrypted), decipher.final()]).toString('utf8');
}
```

> `STOCK_ENCRYPTION_KEY` **jangan** disimpan di `.env` biasa untuk production — taruh di secret manager (Vault/Doppler/AWS Secrets Manager), sesuai checklist security modul Auth sebelumnya.

## 9. Restock via Upload .txt (Auto-grouping per `keysPerUnit`)

```typescript
// stock.service.ts
async restockFromText(productId: string, rawText: string) {
  const product = await this.productsService.findById(productId);
  const lines = rawText.split('\n').map((l) => l.trim()).filter(Boolean);

  if (lines.length % product.keysPerUnit !== 0) {
    throw new BadRequestException(
      `Jumlah baris (${lines.length}) harus kelipatan dari keysPerUnit produk ini (${product.keysPerUnit})`,
    );
  }

  const units = [];
  for (let i = 0; i < lines.length; i += product.keysPerUnit) {
    const chunk = lines.slice(i, i + product.keysPerUnit).join('\n');
    units.push({
      productId,
      encryptedContent: encryptContent(chunk),
      status: 'AVAILABLE' as const,
    });
  }

  await this.db.insert(stockUnits).values(units);

  // Setelah restock, coba auto-fulfill order yang lagi PENDING (FIFO), best-effort
  await this.tryAutoFulfillPendingOrders(productId);
}
```

## 10. Security Checklist — Marketplace Module

- [x] Konten `StockUnit` (API key/link) dienkripsi AES-256-GCM, tidak pernah plaintext di DB  (`STOCK_ENCRYPTION_KEY` dari env, lihat `src/common/crypto/stock-crypto.util.ts`)

- [x] Assignment StockUnit pakai DB transaction + `FOR UPDATE SKIP LOCKED` — cegah race condition  (`StockService.assignAvailableUnit`)
- [x] StockUnit baru ditandai `SOLD` **setelah** payment dikonfirmasi, bukan saat order dibuat  (checkout tidak sentuh stok; assign baru di `confirmPayment`)

## 12. Implementasi Aktual (status Juli 2026)

> Core flow selesai dikerjakan: Products (CRUD + katalog publik), Stock (restock `.txt` + manual, assignment `FOR UPDATE SKIP LOCKED`), Orders/checkout, Payments (manual confirm → auto-assign), Content delivery (anti-IDOR), Warranty fields (schema + DTO), Pending orders per produk. Refund/Review/gambar ditunda.

### Yang sudah berjalan
- **Schema (migrasi `0001_marketplace.sql`)**: tabel `products`, `stock_units`, `orders`, `order_items`, `fulfillments`, `audit_logs`; enum `user_role` diubah jadi `['user','god']` (rename + recreate + `USING` cast). Diterapkan via `psql "$DATABASE_URL" -f ...`.
- **Schema (migrasi `0002_warranty_fields.sql`)**: kolom `warranty_period_days` dan `max_warranty_claims` di tabel `products`.
- **Crypto**: `src/common/crypto/stock-crypto.util.ts` — AES-256-GCM, key 32-byte hex dari `STOCK_ENCRYPTION_KEY` (validasi env). Format base64: `iv(12) | authTag(16) | ciphertext`.
- **Audit + notif**: `audit-logs/audit-logs.service.ts` — `record(tx, input)` bisa join transaction (atomic), `notify()` stub `console.log` (mirip email stub Auth).
- **Products**: `products.service.ts` (create/update/remove + warranty fields, katalog publik + `stockStatus` AVAILABLE/OUT_OF_STOCK tanpa expose angka, `findPendingOrders` dengan buyer name/email), `products.controller.ts` (publik), `products-admin.controller.ts` (`@Roles('god')` CRUD + restock + pending-orders).
- **Stock**: `stock.service.ts` — `restockFromText` (chunk per `keysPerUnit`, encrypt, insert, auto-fulfill), `addManualUnit`, `assignAvailableUnit` (`FOR UPDATE SKIP LOCKED`), `manualAssign` (override), `tryAutoFulfillPendingOrders`/`fulfillOrderIfReady` (FIFO, rollback kalau stok kurang).
- **Orders**: `orders.service.ts` — `checkout` (TIDAK sentuh stok; snapshot harga), `findOwnOrders`, `findOwnOrderById` (dengan flag `hasContent`), `getDecryptedContentForItem` (anti-IDOR: cek kepemilikan order + item milik order), `setPaymentNote`.
- **Payments**: `payments.service.ts` + `ManualPaymentProvider` (abstraksi `PaymentProvider`). `confirmPayment` jalankan tx: validasi status `PENDING_PAYMENT_CONFIRMATION` → set `PAID_PENDING_FULFILLMENT` → assign unit tiap item → `FULFILLED` kalau semua dapat, audit + notify.
- **Storage & Image Upload**: `storage.service.ts` + `storage.controller.ts` — upload gambar via `POST /storage/upload` (multipart, server-side compression dengan sharp: resize max 1200px → WebP quality 80%), upload ke Cloudflare R2, attach ke `products.imageUrl` atau `orders.paymentNote`. Legacy pre-signed URL flow tetap tersedia (`request-upload` + `confirm-upload`) dengan magic bytes validation. Bug fix: `ContentLength` dihapus dari pre-signed URL agar tidak require exact 5MB.
- **Dependencies baru**: `sharp` 0.35.3 (image processing), `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` (R2/S3 client), `@types/multer` 2.2.0.
- **Wiring**: `MarketplaceModule` (controllers + providers) ditambah ke `AppModule`. Script `pnpm seed:god <email>` untuk promosi user ke `god`.
- **Tests**: 6 unit test untuk warranty fields & pending-orders. E2E test existing tetap lulus. Build sukses.

### Keputusan desain penting
- **Role `god` (bukan `admin`).** Semua endpoint admin di-guard `@Roles('god')`. Enum `user_role` sekarang hanya `['user','god']`.
- **Checkout tidak assign stok.** Assignment baru terjadi saat admin konfirmasi pembayaran — sesuai prinsip "unit ditandai SOLD setelah payment dikonfirmasi".
- **Auto-fulfill saat restock.** `restockFromText` memanggil `tryAutoFulfillPendingOrders` sehingga order yang antri (`PAID_PENDING_FULFILLMENT`) langsung terisi begitu stok tiba.
- **Warranty fields sebagai persiapan.** Kolom `warrantyPeriodDays`/`maxWarrantyClaims` sudah ada di schema & DTO, tapi full flow claim (approve/reject, revoke, ganti unit) masih ditunda.
- **Pending orders endpoint.** `GET /products/admin/:id/pending-orders` menampilkan order `PENDING_PAYMENT_CONFIRMATION` dan `PAID_PENDING_FULFILLMENT` untuk produk tertentu, dengan buyer name/email.
- **Upload gambar via server-side compression.** Client upload via `POST /storage/upload` (multipart), server kompres dengan sharp (max 1200px → WebP 80%), lalu upload ke Cloudflare R2. Output URL di-attach ke `products.imageUrl` atau `orders.paymentNote`.
- **Dua metode upload:** (1) Rekomendasi: server-side compression via `POST /storage/upload`, (2) Legacy: pre-signed URL via `request-upload` + `confirm-upload`.
- **Refund/Review ditunda.** Tabel `warranty_claims`/`reviews` belum ada; full flow warranty, refund, review ditunda ke fase berikutnya.
