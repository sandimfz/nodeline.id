```typescript
import { users } from './users.schema';

// Simpan HASH dari refresh token, bukan token asli.
```

## 6. Password Hashing (argon2, bukan bcrypt)

```bash
npm install argon2
```

```typescript
// auth.service.ts (bagian hashing)
import * as argon2 from 'argon2';

async hashPassword(plain: string): Promise<string> {
  return argon2.hash(plain, {
    type: argon2.argon2id, // hybrid, paling direkomendasikan OWASP
    memoryCost: 19456,     // ~19 MB, sesuai rekomendasi OWASP 2024+
    timeCost: 2,
    parallelism: 1,
  });
}

async verifyPassword(hash: string, plain: string): Promise<boolean> {
  return argon2.verify(hash, plain);
}
```

> Jangan pernah bandingkan password dengan `===`. Selalu lewat `argon2.verify`, dan jangan bocorkan lewat timing — `argon2.verify` sudah aman dari timing attack.

**Alur refresh token rotation + reuse detection** (bagian paling penting secara keamanan):

```typescript
// auth.service.ts (pseudo-implementasi)
async refreshTokens(rawRefreshToken: string) {
  const tokenHash = this.hashToken(rawRefreshToken); // sha256, bukan argon2 (cukup cepat & deterministik)
  const stored = await this.refreshTokenRepo.findByHash(tokenHash);

  if (!stored) {
    // Token tidak dikenal sama sekali → tolak
    throw new UnauthorizedException();
  }

  if (stored.isRevoked) {
    // REUSE DETECTED: token lama yang sudah di-rotate dipakai lagi.
    // Ini indikasi token dicuri. Revoke SEMUA refresh token milik user ini.
    await this.refreshTokenRepo.revokeAllForUser(stored.userId);
    throw new UnauthorizedException('Token reuse detected, semua sesi di-logout');
  }

  if (stored.expiresAt < new Date()) {
    throw new UnauthorizedException('Refresh token kedaluwarsa');
  }

  // Rotate: revoke token lama, buat token baru
  const newRawToken = this.generateRefreshToken();
  const newTokenHash = this.hashToken(newRawToken);

  await this.refreshTokenRepo.rotate(stored.id, newTokenHash);

  const user = await this.usersService.findById(stored.userId);
  const accessToken = this.signAccessToken(user);

  return { accessToken, refreshToken: newRawToken };
}
```

Poin kunci:
- Refresh token **selalu di-rotate** setiap kali dipakai (tidak reusable).
- Kalau ada yang mencoba pakai refresh token yang **sudah pernah di-rotate**, itu sinyal token dicuri → **semua sesi user di-revoke**.
- Refresh token dikirim via **httpOnly, secure, sameSite=strict cookie** — bukan disimpan di localStorage (rawan XSS).


`guards/roles.guard.ts`

```typescript
import { CanActivate, ExecutionContext, Injectable } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { ROLES_KEY } from '../decorators/roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!requiredRoles) return true;

    const { user } = context.switchToHttp().getRequest();
    return requiredRoles.includes(user?.role);
  }
}
```

`decorators/roles.decorator.ts`

```typescript
import { SetMetadata } from '@nestjs/common';

export const ROLES_KEY = 'roles';
export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles);
```

Contoh pemakaian di controller lain (misal admin module):

```typescript

@UseGuards(JwtAuthGuard, RolesGuard)
@Get('admin/users')
```

## 10. Response Konsisten (Jangan Bocorkan Info)

```typescript
// SALAH — membocorkan apakah email terdaftar atau tidak
if (!user) throw new NotFoundException('Email tidak ditemukan');

// BENAR — pesan generik untuk login & forgot-password
if (!user || !(await this.verifyPassword(user.passwordHash, dto.password))) {
  throw new UnauthorizedException('Email atau password salah');
}
```

Untuk `forgot-password`, **selalu return response sukses yang sama** baik email ditemukan atau tidak — supaya tidak bisa dipakai untuk enumerasi akun terdaftar.

```typescript
async forgotPassword(email: string) {
  const user = await this.usersService.findByEmail(email);
  if (user) {
    // kirim email reset di background, tidak menunggu
    await this.sendResetEmail(user);
  }
  // response selalu sama, tidak peduli user ada atau tidak
  return { message: 'Jika email terdaftar, link reset sudah dikirim.' };
}
```

## 11. Security Checklist — Auth Module

- [x] Password di-hash pakai argon2id, tidak pernah disimpan/di-log plaintext
- [x] Refresh token disimpan sebagai hash (sha256) di DB, dikirim via httpOnly cookie
- [x] Refresh token rotation aktif + reuse detection (revoke all on reuse)
- [x] Access token short-lived (≤15 menit, default `15m`)
- [x] Rate limiting di `login`, `register` (5/menit), `refresh` (10/menit); `forgot-password`/`reset-password` belum ada (fitur ditunda)
- [x] Response `login` tidak membocorkan apakah email terdaftar (pesan generik "Email atau password salah")
- [x] `ValidationPipe` global dengan `whitelist: true` & `forbidNonWhitelisted: true` (+ `transform` & `forbidUnknownValues`)
- [ ] Reset password token: single-use, expired — ⏭️ belum diimplementasi
- [ ] Email verification token expired & single-use — ⏭️ belum diimplementasi
- [~] Semua endpoint auth di belakang HTTPS, cookie `secure: true` di production — ⚠️ flag `secure` dikendalikan env `COOKIE_SECURE` (default `false` di dev; wajib `true` + HTTPS di production)
- [ ] Log percobaan login gagal (untuk deteksi brute-force), tanpa mencatat password — ⏭️ belum diimplementasi (logging terstruktur Pino menyusul)
- [x] Tidak ada informasi sensitif (password hash, refresh token) yang pernah dikembalikan di response API

  - `auth.service.ts` — argon2id hashing, **refresh token opaque** (`nl_rt_<random>`, **bukan** JWT — lebih aman untuk skema rotation DB-backed), hash sha256 di DB, rotation + reuse detection (revoke all sessions), login dengan error generik.
  - `strategies/jwt-access.strategy.ts` — Passport-JWT untuk access token (`Authorization: Bearer`).
  - `guards/jwt-auth.guard.ts`, `guards/jwt-refresh.guard.ts` (custom, ekstrak token dari cookie/body), `guards/roles.guard.ts` (global).
  - `decorators/current-user.decorator.ts`, `decorators/roles.decorator.ts`.
  - `auth.controller.ts` — 5 endpoint aktif: register, login, refresh, logout, me.
- **Bootstrap** (`src/main.ts`, `app.module.ts`): global prefix `api/v1`, helmet, cookie-parser, CORS whitelist (dari `CORS_ORIGINS`), global `ValidationPipe`, `ClassSerializerInterceptor`, `ThrottlerGuard` global + `RolesGuard` global.

### Keputusan desain penting

- **Refresh token = opaque random string, bukan JWT.** Spec awal menyebut `JwtRefreshStrategy`, tapi di implementasi dipilih token opaque + hash sha256 di DB. Alasannya: reuse detection butuh lookup DB per token, dan dengan opaque token kita tidak bocorkan payload apa pun. Access token tetap JWT.
- **Email transport di-skip.** Forgot/reset password & email verification ditunda sampai ada keputusan transport (stub log / SMTP). Lihat `docs/BACKEND.md` urutan pengerjaan.
- **RBAC ditunda ("nanti").** `RolesGuard`, `@Roles()` decorator, dan enum `user_role` (`user/pro/admin/superadmin`) sudah ada & ter-wire sebagai global guard, tapi belum ada route yang memakai `@Roles(...)` dan kebijakan role belum ditegakkan/diuji di alur bisnis.
- **Throttler in-memory.** Belum pakai Redis (belum ada di port 6379). Cukup untuk single-instance dev; upgrade ke shared Redis store saat multi-instance.
